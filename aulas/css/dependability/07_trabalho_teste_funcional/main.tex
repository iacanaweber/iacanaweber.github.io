\begin{tcolorbox}[colback=blue!5, colframe=blue!40, title=\textbf{Contexto: Calculadora de Dano de RPG}, fonttitle=\small]
\small
Em jogos de RPG, o cálculo de dano em combate envolve diversas variáveis: o poder de ataque do personagem, a defesa do alvo, o tipo de ataque utilizado e a possibilidade de um golpe crítico. Neste trabalho, você testará uma função que implementa essa mecânica de combate, aplicando técnicas de \textbf{teste funcional} (caixa preta) para projetar casos de teste e detectar defeitos em versões incorretas da implementação.
\end{tcolorbox}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Especificação da Função}

A função \texttt{calcular\_dano} recebe quatro parâmetros inteiros e retorna um inteiro representando o dano causado:

\begin{lstlisting}[style=code]
int calcular_dano(int poder_ataque, int defesa, int tipo_ataque, int eh_critico);
\end{lstlisting}

\subsection{Parâmetros}

\begin{center}
\begin{tabular}{llll}
\toprule
\textbf{Parâmetro} & \textbf{Tipo} & \textbf{Domínio} & \textbf{Descrição} \\
\midrule
\texttt{poder\_ataque} & \texttt{int} & $[1, 150]$ & Poder de ataque do personagem \\
\texttt{defesa}        & \texttt{int} & $[0, 150]$ & Defesa do alvo \\
\texttt{tipo\_ataque}  & \texttt{int} & $\{1, 2, 3\}$ & 1 = físico, 2 = mágico, 3 = verdadeiro \\
\texttt{eh\_critico}   & \texttt{int} & $\{0, 1\}$ & 0 = normal, 1 = golpe crítico \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Regras de Cálculo}

\begin{enumerate}[nosep]
  \item \textbf{Validação:} Se qualquer parâmetro estiver fora do domínio, retornar \texttt{-1}.
  \item \textbf{Dano base} conforme o tipo de ataque:
  \begin{itemize}[nosep]
    \item \textbf{Físico} (tipo 1): $\text{dano} = \text{poder\_ataque} - \text{defesa}$
    \item \textbf{Mágico} (tipo 2): $\text{dano} = \text{poder\_ataque} - \lfloor\text{defesa} / 2\rfloor$ \quad (divisão inteira)
    \item \textbf{Verdadeiro} (tipo 3): $\text{dano} = \text{poder\_ataque}$ \quad (ignora a defesa)
  \end{itemize}
  \item \textbf{Dano mínimo:} Se $\text{dano} < 1$, então $\text{dano} = 1$.
  \item \textbf{Golpe crítico:} Se \texttt{eh\_critico} $= 1$, então $\text{dano} = \text{dano} \times 2$.
  \item \textbf{Retorno:} O valor final de dano.
\end{enumerate}

\textit{Nota: As regras são aplicadas na ordem acima --- primeiro calcula-se o dano base, depois aplica-se o mínimo, e por fim o multiplicador crítico.}

\section{Tarefas}

\begin{enumerate}
  \item \textbf{Particionamento de Equivalência:}
  \begin{enumerate}[label=\alph*)]
    \item Identifique todas as \textbf{classes de equivalência inválidas} (entradas fora do domínio).
    \item Identifique todas as \textbf{classes de equivalência válidas} (combinações de tipo de ataque e golpe crítico, incluindo subclasses onde o dano mínimo é ativado).
    \item Projete pelo menos um caso de teste por classe.
  \end{enumerate}

  \item \textbf{Análise do Valor Limite:}
  \begin{enumerate}[label=\alph*)]
    \item Identifique as \textbf{fronteiras} de cada parâmetro.
    \item Identifique a fronteira do \textbf{dano mínimo}.
    \item Projete casos de teste para os valores \textit{on} e \textit{off} de cada fronteira.
  \end{enumerate}

  \item \textbf{Suíte de testes:} Consolide os casos de teste em uma tabela com as colunas: \textit{ID, poder\_ataque, defesa, tipo\_ataque, eh\_critico, resultado esperado, técnica, classe coberta}.

  \item \textbf{Execução contra versões incorretas:}
  \begin{enumerate}[label=\alph*)]
    \item Você receberá \textbf{10 versões compiladas} da função como arquivos objeto (\texttt{versao01.o} a \texttt{versao10.o}), cada uma contendo exatamente \textbf{um defeito}. O protótipo da função está no arquivo \texttt{calcular\_dano.h}.
    \item Implemente seus casos de teste usando o framework \textbf{Unity}, disponível em:

    \url{https://github.com/iacanaweber/Unity}

    O projeto está na pasta \texttt{examples/calcular\_dano/}.

    A estrutura já está pronta --- basta adicionar seus testes no arquivo \texttt{test/TestCalcularDano.c}.
    \item Para trocar a versão sob teste, altere a variável \texttt{VERSAO} no \texttt{makefile} (ou passe via linha de comando):
    \begin{lstlisting}[style=code]
# Testar a versao correta:
make VERSAO=correto.o

# Testar a versao 03:
make VERSAO=versao03.o
    \end{lstlisting}
    \item Para cada versão, identifique quais testes \textbf{falharam} e descreva o \textbf{defeito provável}.
  \end{enumerate}
\end{enumerate}

\subsection{Estrutura do Projeto Unity}

O projeto segue a mesma estrutura dos exemplos vistos em aula:

\begin{lstlisting}[style=code,basicstyle=\ttfamily\footnotesize]
calcular_dano/
  src/
    calcular_dano.h       # Prototipo da funcao
    correto.o             # Versao correta (referencia)
    versao01.o ... versao10.o  # Versoes com defeitos
  test/
    TestCalcularDano.c    # Seus casos de teste aqui
    test_runners/
      TestCalcularDano_Runner.c  # Registrar cada teste
      all_tests.c                # Ponto de entrada
  makefile
\end{lstlisting}

\begin{tcolorbox}[colback=blue!5, colframe=blue!40, title=\textbf{Como adicionar testes}, fonttitle=\small]
\small
Em \texttt{test/TestCalcularDano.c}, adicione um teste por caso:
\begin{lstlisting}[style=code]
TEST(CalcularDano, DanoFisicoNormal)
{
  TEST_ASSERT_EQUAL(70, calcular_dano(100, 30, 1, 0));
}
\end{lstlisting}
Em \texttt{test/test\_runners/TestCalcularDano\_Runner.c}, registre cada teste:
\begin{lstlisting}[style=code]
TEST_GROUP_RUNNER(CalcularDano)
{
  RUN_TEST_CASE(CalcularDano, DanoFisicoNormal);
  /* ... demais testes ... */
}
\end{lstlisting}
Compile e execute com \texttt{make} ou \texttt{make VERSAO=versaoNN.o}.
\end{tcolorbox}
