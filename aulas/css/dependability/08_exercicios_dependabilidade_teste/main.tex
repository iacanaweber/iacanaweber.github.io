\section{Parte 1 --- Conceitos de Dependabilidade}

\textbf{Exercício 1.}
Defina, com suas palavras, os conceitos de \textit{fault} (defeito), \textit{error} (erro de estado) e \textit{failure} (falha de serviço). Em seguida, dê um exemplo concreto de software em que um \textit{fault} está presente no código, mas nenhum \textit{error} se manifesta durante a execução normal.

\vspace{8pt}

\textbf{Exercício 2.}
Considere o seguinte cenário: um microsserviço de pagamentos processa uma requisição de débito, mas um bug faz com que o saldo seja decrementado duas vezes quando ocorre um timeout seguido de retry pelo cliente.
\begin{enumerate}[label=\alph*)]
  \item Identifique o \textit{fault}, o \textit{error} e a \textit{failure} neste cenário.
  \item A qual classe de semântica de falha (crash, omission, timing, value, Byzantine) esse comportamento pertence? Justifique.
  \item Proponha um mecanismo para evitar o problema (idempotência, deduplicação ou outro).
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 3.}
Classifique cada situação abaixo na semântica de falha mais adequada (crash, omission, timing, value/response, Byzantine):
\begin{enumerate}[label=\alph*)]
  \item Um servidor web fecha a conexão e reinicia após uma exceção não tratada.
  \item Um sensor de temperatura retorna sempre o valor 25\textdegree C, mesmo quando a temperatura real é 80\textdegree C.
  \item Um serviço responde corretamente, mas após 12 segundos quando o SLA exige resposta em até 2 segundos.
  \item Um nó de consenso envia o valor ``A'' para um peer e o valor ``B'' para outro peer na mesma rodada.
  \item Uma mensagem de heartbeat é enviada pelo servidor, mas se perde na rede e nunca chega ao monitor.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 4.}
Explique a diferença entre \textit{fail-silent}, \textit{fail-stop} e \textit{fail-fast}. Para cada um, dê um exemplo de sistema ou componente que se beneficia desse comportamento.

\vspace{8pt}

\textbf{Exercício 5.}
Um sistema de e-commerce possui a seguinte especificação: ``cada pedido deve ser processado exatamente uma vez''.
\begin{enumerate}[label=\alph*)]
  \item Explique por que a semântica \textit{exactly-once} é difícil de garantir em um sistema distribuído.
  \item Compare as semânticas \textit{at-least-once} e \textit{at-most-once}, indicando vantagens e riscos de cada uma nesse contexto.
  \item Descreva como a combinação de idempotência + chave de deduplicação pode aproximar o comportamento de \textit{exactly-once}.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 6.}
Considere um sistema IoT com os seguintes componentes: sensores, gateway local, rede (Wi-Fi), serviço na nuvem e dashboard de monitoramento.
\begin{enumerate}[label=\alph*)]
  \item Identifique pelo menos 3 fronteiras de contenção (\textit{fault containment regions}) nesse sistema.
  \item Para cada fronteira, descreva: que tipo de erro ela consegue conter e o que ela \textbf{não} consegue conter.
  \item Proponha uma estratégia de detecção para cada fronteira (check semântico, timeout, heartbeat, etc.).
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 7.}
Um serviço A depende de um serviço B. Quando B fica lento, A faz retries agressivos (sem backoff), o que sobrecarrega B e causa uma cascata de falhas.
\begin{enumerate}[label=\alph*)]
  \item Explique o fenômeno de \textit{retry storm} e por que ele amplifica falhas.
  \item Proponha pelo menos 3 mecanismos para mitigar esse problema.
  \item Qual é o papel do \textit{circuit breaker} nesse cenário? Descreva seu funcionamento básico.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 8.}
Compare as quatro estratégias de recuperação abaixo. Para cada uma, dê um cenário em que ela é a mais adequada:
\begin{enumerate}[label=\alph*)]
  \item Restart (reinicialização do processo)
  \item Rollback (checkpoint + retorno ao estado anterior)
  \item Transação (atomicidade garantida por commit/abort)
  \item Compensação (saga: desfazer efeitos parciais em sistemas distribuídos)
\end{enumerate}

\section{Parte 2 --- Confiabilidade e Disponibilidade}

\textbf{Exercício 9.}
Um servidor operou continuamente por 60 dias. Nesse período, ocorreram 4 falhas. Os tempos de reparo foram: 2,0h; 1,0h; 3,0h; 0,5h.
\begin{enumerate}[label=\alph*)]
  \item Calcule o $\MTBF$ (em horas).
  \item Calcule o $\MTTR$.
  \item Calcule a disponibilidade $\A$.
  \item Estime o \textit{downtime} anual desse sistema.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 10.}
Considere dois sistemas reparáveis:
\begin{itemize}[nosep]
  \item Sistema P: $\MTBF = 800\,\text{h}$, $\MTTR = 16\,\text{h}$
  \item Sistema Q: $\MTBF = 200\,\text{h}$, $\MTTR = 1\,\text{h}$
\end{itemize}
\begin{enumerate}[label=\alph*)]
  \item Calcule a disponibilidade de cada sistema.
  \item Qual sistema é mais \textbf{confiável}? E qual é mais \textbf{disponível}?
  \item Explique, em termos práticos, por que confiabilidade e disponibilidade podem apontar para sistemas diferentes.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 11.}
Assumindo o modelo exponencial de falhas com $\MTBF = 1000\,\text{h}$:
\begin{enumerate}[label=\alph*)]
  \item Qual a taxa de falha $\lambda$?
  \item Calcule $\R(200)$, ou seja, a probabilidade de operar sem falha por 200 horas.
  \item Calcule $\R(1000)$.
  \item Se a missão exige confiabilidade de pelo menos 95\% em 100 horas, esse sistema atende?
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 12.}
Uma empresa deseja garantir um SLA de $\A \geq 99{,}9\%$ para sua plataforma. O sistema atual tem $\MTBF = 500\,\text{h}$.
\begin{enumerate}[label=\alph*)]
  \item Qual deve ser o $\MTTR$ máximo para atender esse SLA?
  \item Com esse $\MTTR$ máximo, estime o \textit{downtime} anual permitido.
  \item Se na prática o $\MTTR = 2\,\text{h}$, o SLA é atendido? Justifique.
\end{enumerate}

\vspace{8pt}

\textbf{Exercício 13.}
Diferencie $\MTTF$ e $\MTBF$. Em que tipo de sistema cada métrica é mais apropriada? Dê um exemplo para cada.

\vspace{8pt}

\textbf{Exercício 14.}
Um sistema deve operar continuamente por 48 horas para uma missão crítica. Duas opções estão disponíveis:
\begin{itemize}[nosep]
  \item Opção A: $\MTBF = 400\,\text{h}$
  \item Opção B: $\MTBF = 1200\,\text{h}$
\end{itemize}
\begin{enumerate}[label=\alph*)]
  \item Calcule $\R(48)$ para cada opção (modelo exponencial).
  \item Qual o ganho em pontos percentuais de confiabilidade da opção B sobre a opção A?
  \item Se o custo da opção B é 3$\times$ maior, você recomendaria a troca? Justifique considerando o contexto de missão crítica.
\end{enumerate}

\textbf{Exercício 24.}
Uma função recebe um inteiro \texttt{idade} e retorna uma string conforme as regras:

\section{Parte 6 --- Integração: Dependabilidade e Teste}

\textbf{Exercício 33.}
Considere uma função que implementa um mecanismo de retry com backoff exponencial:

\begin{lstlisting}[style=code]
int retry_request(int max_retries) {
    int tentativas = 0;
    int sucesso = 0;
    while (tentativas < max_retries && sucesso == 0) {
        sucesso = enviar_requisicao();
        if (sucesso == 0) {
            tentativas++;
            esperar(tentativas * 2); // backoff
        }
    }
    return sucesso;
}
\end{lstlisting}

\begin{enumerate}[label=\alph*)]
  \item Projete casos de teste de caixa branca para cobrir todas as ramificações deste código.
  \item Projete casos de teste de caixa preta considerando as classes de equivalência: sucesso na primeira tentativa, sucesso após retries, falha após esgotar tentativas.
  \item Este código implementa adequadamente backoff exponencial? Se não, identifique o problema.
  \item Do ponto de vista de dependabilidade, que mecanismos adicionais poderiam ser incorporados (jitter, circuit breaker, etc.)?
\end{enumerate}

  \item Calcule $\R(48)$ (modelo exponencial) antes e depois.
  \item De que forma teste de software contribui para \textbf{prevenção de falhas} (remoção de \textit{faults})?

\end{enumerate}

\textbf{Exercício 35.}
Considere a seguinte especificação de um mecanismo de idempotência:

\begin{lstlisting}[style=code]
int processar_pedido(int pedido_id, int valor) {
    if (pedido_id <= 0 || valor <= 0) {
        return -1; // entrada invalida
    }
    if (ja_processado(pedido_id)) {
        return buscar_resultado(pedido_id); // replay
    }
    int resultado = debitar(valor);
    registrar(pedido_id, resultado);
